Catatan & Best Practice

    Metodologi

    Rumus kapasitas
    • S = ukuran sumber × (1 + growth)tahun; g = global dedup vendor
    • Full F = S × (1 − reduction) × (1 − g); incremental I = S × (1 − reduction) × (1 − g/2) × change rate
    • Restore point harian tersimpan P menurut tipe target:
      • Block repo, forever incremental: retensi + 1; dengan weekly full: retensi + 6
      • Veeam Hardened Repository: max(retensi, immutability) + 7
      • Object storage Object Lock (block generation): max(retensi, immutability) + 10
      • Platform dedup tanpa lock: retensi + 1; dengan retention lock/WORM: max(retensi, immutability) + 1
      • Commvault cloud WORM (DDB seal): 2 × max(retensi, immutability)
    • Short-term: forever incremental / Fast Clone + synthetic = F + (P − 1) × I (+1% F metadata per synthetic full); tanpa Fast Clone / active full = K × F + (P − K) × I, K = ⌈P / 7⌉.
    • GFS di luar jendela harian disusun sebagai timeline; tiap titik menyimpan blok unik terhadap titik sebelumnya: Fc × (1 − (1 − d)√N) (realistis) atau (1 − d)N (konservatif). Tanpa Fast Clone / active full = F per titik.
    • Log database = S × log% × (1 − reduction) × (1 − g/2) × P. Kebutuhan = total × (1 + buffer).
    Rumus resource & lisensi
    • Throughput = max(data berubah harian ÷ backup window, total data ÷ window full). Throughput dibagi kapasitas per task/node/engine menghasilkan jumlah proxy, MediaAgent, atau node.
    • Server manajemen (VBR, CommServe, PPDM, HYCU, IBM SP) dipilih per tier berdasarkan jumlah objek atau ingest harian.
    • Lisensi kapasitas (FETB) = total data sumber pada tahun proyeksi, di luar Microsoft 365 (dihitung per user).

    Semua rasio dan sizing adalah angka perencanaan berbasis guideline publik vendor yang dibulatkan. Validasi dengan sizing tool resmi vendor dan data change rate riil sebelum pengadaan.
