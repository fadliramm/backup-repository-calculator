Backup Repository Calculator

Hitung kapasitas repository backup untuk skenario Non-Immutable dan Immutable secara berdampingan. Pilih workload; parameter default diisi otomatis berdasarkan best practice masing-masing workload dan bisa diubah.

Pengaturan Global

Buffer untuk ruang kerja synthetic full/merge, lonjakan perubahan data, dan agar filesystem tidak penuh (rekomendasi 15–25%).

Repository

Workload

Data reduction = gabungan kompresi + deduplikasi inline backup (50% ≈ rasio 2:1). Change rate = persentase data sumber yang berubah per hari. Log/hari hanya untuk database (transaction/archive log).

Catatan & Rekomendasi

    Metodologi

    Rumus yang dipakai
    • S = ukuran sumber × (1 + growth)tahun
    • Full F = S × (1 − data reduction); Incremental I = F × change rate
    • Jumlah restore point harian yang tersimpan (P):
      • Forever forward incremental: retensi + 1 (titik merge)
      • Forward incr. dengan weekly full: retensi + 6 (chain lama baru bisa dihapus setelah full berikutnya cukup tua)
      • Hardened repo: max(retensi, immutability) + 7
      • Object storage: max(retensi, immutability) + 10 hari block generation
    • Short-term: dengan Fast Clone + synthetic full = F + (P − 1) × I + (K − 1) × 1% F (metadata); tanpa Fast Clone / active full = K × F + (P − K) × I, dengan K = jumlah full dalam jendela = ⌈P / 7⌉. Forever incremental = F + (P − 1) × I.
    • GFS (weekly/monthly/yearly) di luar jendela short-term disusun sebagai timeline restore point. Dengan Fast Clone/object storage, tiap titik menyimpan blok unik terhadap titik sebelumnya: F × (1 − (1 − d)√N) (realistis/hotspot) atau F × (1 − (1 − d)N) (konservatif/acak), N = jarak hari. Tanpa Fast Clone atau dengan active full = F per titik.
    • Log database = S × log% × (1 − reduction) × P.
    • Kebutuhan = total × (1 + buffer).

    Mode "Realistis" mengasumsikan perubahan harian sebagian besar menimpa blok yang sama (hotspot), sehingga perubahan kumulatif tumbuh sublinear. Mode "Konservatif" mengasumsikan perubahan blok acak dan memberi angka batas atas. Validasi dengan data change rate riil dari monitoring (mis. Veeam ONE) bila tersedia.
